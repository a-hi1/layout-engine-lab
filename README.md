## 为什么做这个

我在一个 25 万行的开源画布项目上做深度二开时，有一块最难的算法：**一键排版**。

用户把几十个节点拖得乱七八糟，按钮点下去，需要在一秒钟内把它们排成能看懂的层次结构，而且**不能改变图的语义**——连线代表依赖关系，排错了就是排错了。

这个仓库把那块算法**单独抽出来，从零重写成一个可玩的实验台**。

> **作者注**：这个文件里没有一行上游代码。算法是我自己实现的，
> 目的是把这个能力从"我改过某个项目"变成"你可以现在就点开玩"。

## 算法

本质是 **Sugiyama 分层图绘制**的一个简化实现，分四步：

### 1. 分层（最长路径）

对每条边 `a → b`，反复松弛 `layer[b] = max(layer[b], layer[a] + 1)`，直到不再变化。

效果：一个节点一定排在它所有前驱的右边，**依赖关系从左到右一眼能读**。

### 2. 层内排序（barycenter）

每一层内部，按「邻居的平均位置」排序：

```text
weight(v) = average( row( 与 v 相邻的上一层的节点 ) )
```

上下交替扫描 4 轮（下行用前驱、上行用后继），让每一层都尽量对齐它依赖的那一层。

### 3. 坐标分配

第 `c` 层 → `x = (c - (n-1)/2) * COL_GAP`；层内第 `k` 个 → `y = (k - (m-1)/2) * ROW_GAP`，整体以画布中心为原点。

### 4. 局部交换优化

barycenter 只是启发式，不保证最优。所以最后再做一轮**爬山**：

对每一层，尝试交换相邻两个节点，如果整体交叉数下降就保留，否则换回。最多 4 轮，出现无改进即停。

> 这一步不是必须的，但它能把结果从「看起来还行」压到「明显更整齐」。

## 两个指标是怎么算的

**连线交叉**：把每条边当作一条从起点节点中心到终点节点中心的线段，两两做线段相交测试。共用一个端点的两条边不计入。

**节点重叠**：两两比较节点包围盒，横纵方向的中心距同时小于 0.92 倍节点尺寸，就算一对重叠。

> 这两个数都是**几何事实**，不是估出来的评分。
> 你可以拖动任意节点，看着数字实时变化——它不会骗你。

## 技术实现

- **Canvas 2D** 单画布渲染，`devicePixelRatio` 适配高分屏
- **零依赖**，没有任何框架、构建工具、CDN 请求
- 状态很小：`nodes / edges / groups / view / selection / history`
- 动画统一走 `requestAnimationFrame` + cubic ease，并带一个 **`setTimeout` 兜底**：
  切到后台导致 rAF 被节流时，排版也会在 `dur + 90ms` 内强制落位，不会卡在中间态
- 历史记录用整图快照（60 步上限），比命令式 undo 简单，而且不会漏状态
